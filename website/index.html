For you. And your agents.

An agent interface.
Your actual workspace.

Give an agent a native API to the terminals you already use. It can find tabs, read screens and retained output, wait for changes, and send guarded input locally or over SSH.

Inspection leaves your focus, scroll position and terminal size alone. Optional shell integration reports command completion and exit status.

Small on purpose.

Native where it matters.

Built with Rust, GTK, WebKitGTK and a terminal engine derived from st. Native Wayland and X11 support, with a lightweight launcher.

Settings that travel.

Reuse supported Alacritty font, color and scrollback settings. Worminal settings sync on peer connection, merging independent edits and reporting conflicts. Compatible peers also sync daemon versions.

Configuration reference ↗

Resources are part of the design.

Hidden busy tabs avoid streaming terminal frames. Reviewed CPU and network limits are checked in the test suite. The device registry has no background discovery scans or heartbeats.

A few practical questions.

What happens when I close the last window?

Your terminal programs keep running in the background service. Reopen the workspace with worminal --attach. Closing a terminal tab, or stopping its service, ends that tab’s session.

Does it restore running programs after a reboot?

No. Keeping a session alive and recovering after a restart are different things. Restart recovery opens fresh shells in saved directories and restores browser URLs; it does not replay commands or restore running processes.

Can I use it on remote and headless machines?

Yes. Connect to a compatible Linux host with worminal --master user@host. The remote machine runs the Worminal daemon; it does not need the graphical interface. Read the remote installation guide.

Where do I get it?

Worminal is free, open-source software for Linux. Get the source on GitHub and follow the build and installation instructions. The native commands also include help for configuration and the agent API.
