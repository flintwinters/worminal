Combined Worminal preview
=========================

Status: implemented on gtk-preview as separate worminal-preview and worminald-preview
executables. The original launcher, installation files and live v1 services remain
available. No default-launcher switch or deployment has been performed.

Architecture
------------
GTK 3 owns windows, the ordered notebook strip/content stack, input methods and
clipboard. Pango/Cairo uses Fontconfig/FreeType fonts and fallback faces, with the
compiled Alacritty palette, compact cell spacing and glyph offsets. The original
st parser, history, selection and reflow remain authoritative. Both frontends use
src/terminal/keymap.inc and all executable roles share src/terminal/defaults.c.
There are no frontend XIDs, Xft calls, GtkPlug/XEmbed
widgets, or dependencies on a surf executable.

The preview daemon compiles the same service/terminal sources without GTK,
WebKit, X11 or Xft libraries. Its v2 endpoint and SSH executable name are distinct
from v1. Browser records carry an explicit kind and saved URL; no terminal session
or PTY is allocated. Browser focus/resize cannot resize or create a PTY. Created
records have explicit identity acknowledgments. Attach creates no shell.

The frontend opens service connections off the GTK thread, reads framed messages
incrementally through GLib watches, bounds outbound queues and yields output
floods to GTK input/redraw work. Keys received before the first catalog are kept.
Disconnect drops unsent input, reports it, and reconnects without replaying it.
Stale focus reports and allocation-only resize messages cannot reclaim another window's controller. SSH child exits
are watched; local services detach from the launching view.

Every service PTY uses nonblocking writes and an ordered input queue bounded to
1 MiB, including parser replies after echo/CRLF translation. One readiness turn
writes at most 16 KiB. Saturation reports an error and stops only that tab; this
is an explicit overload policy, not reliable delivery for arbitrarily large
pastes. Other tabs and new shell creation remain responsive.

Browser policy
--------------
WebKitGTK 4.1 is normally linked. Its context is constructed only when a browser
page is selected; unselected shared browser links create no WebKit objects.
Cookies, local storage, page execution, forms and navigation history stay local.
Persistent data/cache use the XDG worminal-preview directories. Only saved URLs
cross the workspace socket. A peer's URL update never replaces an existing local
page, form or history. Existing views do not follow a peer's navigation.

The browser provides Back, Forward, Reload/Stop, titles and location entry.
Ctrl+Shift+B opens a new-link dialog; --surf URL creates a browser tab directly.
Ctrl+L selects the active browser's address. Terminal CLI commands, local launch
environments, remote account environment inheritance, tab/window shortcuts,
selection, clipboard, input methods, mouse reporting and zoom use GTK equivalents.

User popup requests open their requested link in an independent browser tab.
window.open returns null and no window.opener relationship is retained. Related
WebKit popup construction crashed in the installed WebKitGTK 2.50.6 during the
integration test; the preview instead intercepts create/navigation requests and
opens ordinary independent views. Popup workflows that require an opener or
write into a newly created blank window are therefore outside current parity.

Downloads use a GTK save chooser with overwrite confirmation. Geolocation,
camera/microphone and notifications use explicit allow/deny dialogs; unsupported
permission types are denied. Page fullscreen requests are declined. Certificate
failures are displayed and never bypassed. Renderer failures show a Reload action.
JavaScript, images, strict TLS and local storage are enabled; media requires a
user gesture, third-party cookies and WebGL are disabled, following the relevant
conservative surf defaults. No surf configuration/scripts are implicitly loaded.

Validation and measurements
---------------------------
All generated profiles, logs, fixture certificates, screenshots and compositor
runtime files live under .checks. The project-local virtual input seat is pinned
to the Weston 10 ABI (Debian 12); a custom WORMINAL_WESTON must provide a seat.
Management entrypoints:

  build-preview               compile the preview and its isolated daemon
  check-headless              parser plus v1/v2 service regressions
  check-preview               GTK/WebKit checks on private Xvfb
  check-preview-keys          existing navigation and wheel tests through GTK
  check-preview-wayland       headless Weston, GDK Wayland, DISPLAY absent
  check-preview-qtile         private Xvfb/Qtile, two visible tiled windows
  prove-preview-regressions  require counterfactual blocked-PTY/resize-ownership/read-capacity failures
  preview-perf                compare launch/input latency and helper-inclusive memory

Verified gates: all three frontend backends (local and SSH fixture), the five GTK
input tests, all 54 original/headless unit tests, static analysis, and all three
counterfactual regression proofs pass.

The integration runner exercises local connections and the real SSH bridge via a
local ssh fixture. It checks UTF-8 and early input, sustained output, scrollback,
resize/zoom/reflow, selection, clipboard, IME commit, controller transfer,
reconnect, browser allocation, navigation, forms, cookies/local storage,
shared-link independence, popups, download saving, notification denial, invalid
TLS, renderer recovery and tab close/reopen. GTK critical diagnostics are fatal.
The original X11 suite remains the regression gate. Counterfactual builds prove
the blocked-PTY, stale-resize ownership and sizeof(pointer) read-capacity regressions fail without fixes.

Before implementation, private-Xvfb launch-to-echo measured 22.4 ms median,
33.5 ms p95 (20 trials); interactive-shell input readiness measured 157.4 ms
median, 164.5 ms p95. A later original/preview comparison is recorded below.
These are warm-cache, local-machine measurements, not cold-cache guarantees.
Input timings include the xdotool process/injection round trip. RSS sums can
count shared pages more than once; PSS is also reported. Browser totals include
its WebKit network and renderer helper processes. Daemon totals include its shell.

Comparison recorded on 2026-10-18 (20 launch trials):

                                Original       Preview
  Launch to echo median/p95      24.2/33.2 ms   141.8/165.8 ms
  Shell input median/p95         160.5/169.5 ms  280.0/291.5 ms
  Original terminal: input median 3.18 ms; frontend RSS/PSS 8.0/3.2 MiB
  Preview terminal: input median 3.01 ms; frontend RSS/PSS 117.5/59.5 MiB
  Preview mixed: input median 7.45 ms; frontend/helpers RSS/PSS 398.6/192.4 MiB (3 processes)
  Service plus shell RSS stayed approximately 3.4-3.6 MiB.

The detailed machine-local results are .checks/preview-performance.json. The
preview's startup and memory overhead is substantial; retaining the original
launcher is the current rollout decision, pending review and optimization.

Limits still requiring review
-----------------------------
This is a separate preview, not a terminal-parity or website-compatibility claim.
Live remote hosts, compositor-specific IME composition/candidate windows, camera
and geolocation allow paths, notification delivery, large real-world pages,
restart-persistent browser history/forms, and pixel-exact Xft/Pango font parity
have not all been established by the automated fixtures. Per-view back/forward
history and forms survive hiding a tab, not destroying its browser view. Cookies
and local storage persist in the local profile.

Placement and resizing obey compositor/window-manager policy. -g accepts terminal
cell dimensions; positional suffixes cannot force placement on Wayland. XEmbed
-w is intentionally unsupported. Dedicated file-opening commands and inline
terminal graphics remain outside this release. Frontend print-to-stdout (-o -)
requires a consuming reader. The service and terminal sessions survive frontend
exit; only explicit close/stop operations end them.
